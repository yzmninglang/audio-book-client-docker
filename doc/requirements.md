# 需求与边界清单(定稿)

状态:【已确认】(2026-10-03)

## 1. 系统定位

| 维度 | 定位 |
|---|---|
| 角色 | **纯客户端**,不包含任何推理算力 |
| 部署形态 | **NAS 服务端**:Docker 容器部署在 NAS,局域网内用浏览器访问 |
| 交互 | Web 页面 |
| 后端 | 远端 TTS 引擎(IndexTTS),通过 HTTP 调用,地址可配置 |
| 目标架构 | x86_64 |

> 原始需求描述为「客户端放在客户机上」,经 2026-10-03 决策改为**NAS 服务端形态**。此变更要求路径选择器
> 必须是「服务端卷内路径浏览器」而非系统文件对话框,详见 [architecture.md](architecture.md)。

## 2. 核心设计动机

需求方明确指出:后端 TTS 引擎后期**可能变动甚至更换**。因此本系统必须:

1. **TTS 连接模块**与**音频处理模块**彻底解耦(见 [architecture.md](architecture.md) 硬规则 R1)
2. 支持**可配置重试次数**,错误按可重试性分层
3. JSON 中的人物需**映射到各自的音色**
4. 支持**手动填写后端 URL** + **测试连接**按钮
5. **新增后端必须能增量接入**:接口规范、传参方式都可能与 IndexTTS2 不同,
   新后端应作为**新增适配器**加入,而**不是**回头修改现有适配器去兼容

> 第 5 条是硬要求,它约束了领域模型的形状:任何 IndexTTS2 专有的概念
> (模式枚举 `emo_control_method`、9 个生成参数、裸 `bytes` 参考音色)**不得进入领域层**。
> 落实方式见 [tts/design.md §6](tts/design.md#6-领域抽象修正-indextts-细节泄漏)。

## 3. In-Scope(核心功能)

| # | 功能 | 说明 |
|---|---|---|
| 1 | 工程管理 | 新建工程(路径导入 **或** 浏览器上传)/ 扫描既有工作区 / 工程列表 / 打开工程 |
| 1b | 章节导入 | 给已有工程**追加/替换章节**(浏览器上传,同名覆盖) |
| 2 | 目录规范 | `<工作区>/<书名>/{json/, process_audio/, audio/}` |
| 3 | 章节解析 | 读取章节 JSON,聚合出**角色列表**(跨章去重) |
| 4 | 音色库管理 | 二级页面:列表 / 新建 / 重命名 / 编辑 / 删除;解析既有 `reference/audio` 结构 |
| 5 | 角色→音色绑定 | 每个角色一个**可搜索下拉框**,工程内持久化;多角色可共用同一音色 |
| 6 | TTS 连接层 | URL 配置 + 测试连接 + 分层重试 + 超时 + 参考音频 base64 缓存 |
| 7 | 音频预处理层 | 真实格式探测 / 转码 / 裁剪 / base64 编解码 |
| 8 | 合成引擎 | 串行队列、逐条合成、进度展示、开始/暂停/停止 |
| 9 | 断点续传 | 扫描 `audio/` 与 `process_audio/`,只补未完成部分 |
| 10 | 章节拼接 | 按 `delay` 插静音 → 拼接 → 章节成品 → 成功后清理 `process_audio/` |

## 4. Out-of-Scope(明确排除)

- TTS 引擎的部署、模型管理、训练(本项目只当调用方)
- 文本预处理:分句、角色识别、情感标注(章节 JSON 已提供这些信息)
- 波形编辑、人工试听校对、批量重录
- 多用户、权限、登录、云端同步(局域网可信环境)
- 全书合并为单文件(仅做章节级成品)

## 5. 已确认的关键技术决策

| 项 | 决策 | 依据 |
|---|---|---|
| 技术栈 | Python FastAPI(uv 管理)+ Vue3 | 用户确认 |
| 后端契约 | `POST /api/tts`,JSON + base64 音频 | 实测确认 |
| 合成粒度 | 按 JSON **逐条**(契约锁定,非可选) | `emo_vector`/`delay` 均为逐条 |
| 零向量处理 | 仍走 `emo_control_method=2` 透传 | 用户确认;实测后端不归一化,零向量 ≈ 无情感引导 |
| 向量校验 | 客户端按 **0.8** 之和卡口,超出则缩放后再发 | 实测:后端只拒 >1.5,0.8~1.5 是危险区 |
| 音色入库 | 转码为 **mono + 只降不升(≤22050)** + 裁剪 ≤15s | 实测压缩比 3.7× |
| 章节成品 | **22050Hz mono 原样拼接,0 重采样** | 实测:后端输出恒 22050 mono |
| 并发 | 默认**串行 1**(后端无锁、无并发保护) | 实测确认 |
| 重试 | 分层:400 不重试 / 500 退避重试 | 实测:400 为参数/数据错,重试无意义 |

## 5.1 需求扩展记录

| 日期 | 扩展 | 原因 |
|---|---|---|
| 2026-10-03 | **新增「浏览器上传 JSON」**(上传建工程 + 追加章节) | 实现完成后用户实际使用时发现:浏览器无法上传 JSON,只能先把书拷到 NAS 卷里再用路径浏览器选中。而**音色库是支持浏览器上传的**(`POST /api/voices` 为 multipart),两者不对称会让人困惑。经用户确认后扩展。 |

## 6. 小决策(【默认采纳】,用户未提出异议)

| 项 | 处理 |
|---|---|
| `pt.txt` | 保留为音色元数据存储(当前后端 API 用不上,换引擎时可能需要) |
| `delay` | 理解为「本条之后」的静音时长,拼接时插入 |
| 新建工程 | 包含「创建目录结构 + 把 JSON 导入 `json/`」 |
| 扫描目录 | 路径可配置(默认取工作区卷根),不写死 |

## 7. 术语表

| 术语 | 定义 |
|---|---|
| 工作区 Workspace | 存放多个书籍工程的根目录(容器内 `/workspace`) |
| 工程 Project | 一本书的隔离空间:`<工作区>/<书名>/` |
| 章节 Chapter | 工程内一个 JSON 文件,对应一个成品音频 |
| 片段 Fragment | 一条 JSON 项的合成结果,续传的最小单元 |
| 音色 Voice | 音色库中的一个目录(含参考音频 + 参考文本 + 可选情感参考集) |
| 绑定 Binding | 「角色 → 音色」的映射,工程内持久化 |
| manifest | 工程的续传台账文件,记录章节/片段状态 |

## 8. 验收要点(从需求反推)

1. 手动填 URL → 点测试连接 → 能区分「连不上」「模型未加载」「参数错」三种失败
2. 打开工程 → 自动列出所有角色 → 每个角色可搜索下拉绑定音色
3. 中断生成后重开 → 点「全部开始」→ 只补未完成部分,不重做已完成章节
4. 章节完成后 `audio/` 出现成品,`process_audio/` 被自动清理
5. 音色库可新建/重命名/编辑/删除
